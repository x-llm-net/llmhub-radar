# 密钥多渠道路由

本规则用于 `mode: channels` 策略，替代旧的厂商、模型倍率和服务档位选择。生产版本应从部署状态确认。

## 选择与范围

- 每个根域名对应一个总代理。根域名只展示其 Owner 自有渠道商的渠道；渠道商子域名展示当前渠道商的渠道。
- 密钥持久化有序 `channel_ids` 和服务端校验的 `provider_id`。前端以渠道为选择对象，展示当前倍率和支持模型，允许调整顺序。
- 请求按具体模型筛选已选渠道，再按倍率首次出现的顺序尝试。同倍率保留现有健康筛选、优先级、权重和渠道亲和；接口类型只用于请求兼容校验。
- 渠道商修改倍率后，所有引用该渠道的密钥在后续请求使用新倍率。新增并发布模型自动生效，不要求重存密钥。
- 不保存密钥级模型或价格快照。一次请求解析当前配置后使用同一份运行时策略；最终计费和历史收益继续保留已有账务快照。

## 不可用与兜底

- 整条渠道下架、禁用或健康隔离后，不参与实际服务，但仍保留其已发布模型和当前倍率作为兜底依据。
- 单个模型取消发布或从渠道配置移除后，该渠道不再提供该模型的依据。渠道彻底删除后，同样不再提供依据。
- 请求模型不在任何仍存在的已选渠道的已发布模型内时，明确报错，不允许全局兜底获取新模型权限。
- 已选渠道都不可用或尝试失败后进入全局兜底，允许跨总代，也允许同渠道商未被选中的其他渠道。已选渠道和本次失败渠道不重复进入兜底。
- 先选择低于该模型首选倍率的合格渠道；没有时选择不超过已选最高倍率的合格渠道。沿用现有健康隔离状态，不新增评分阈值。
- 已选且符合条件的渠道各最多尝试一次。兜底阶段最多 `RetryTimes + 1` 次；不可重试错误、取消和固定异步任务限制继续适用。
- 亲和仅在当前可用的倍率阶段内生效，不能跳过更优先的倍率或恢复后的首选阶段。

## 计费与升级

- 普通命中按实际服务渠道当前倍率计费。兜底倍率低于首选倍率时按首选倍率向用户收费；供给收入仍按实际服务倍率计算，差价沿用平台与原渠道商分成。
- 管理和搜索范围与全局兜底范围分开校验。跨总代实际服务沿用现有供给归属和分账。
- 旧策略不再执行。保留密钥、余额、状态、渠道和历史账务，密钥列表标记需要重新配置；用户重新选择渠道后恢复调用。旧策略不能回落到传统分组路由。
- 已提交异步任务的结算仍使用原有 `TaskBillingContext` 和待结算收益记录，不因本次升级重新定价。
- 本次无删除用户数据或账务数据的数据库迁移。发布前确认旧密钥重新配置的影响；回滚可恢复旧程序，但本版本创建或改为新策略的密钥需要在旧界面重新配置，不能视作无影响回滚。

## 后续事项

总代理可指定哪些下属渠道商的渠道进入用户搜索入口。当前只记录这个扩展方向，不开放整个下属渠道目录。
