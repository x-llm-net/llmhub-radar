# 服务档位路由加固清单

状态：审查完成，按批次修复中。本文件记录当前仍需处理的风险、已确认决策和验收条件；完成项应保留并标记状态，避免同类问题再次引入。

## 已确认决策

- 供给倍率统一使用小数倍率：`1.0 = 1x = 100%`，`0.1 = 0.1x = 10%`。管理页面必须明确显示 `x`，不得用 `100` 表示无限或 100%。
- 高品质档是“质量资格 + 价格保护”，不是 `medium` 之上的连续价格区间。首版高品质最高供给倍率保护建议为 `1.0`，以后由管理员配置。
- 同一个 `Channel + Model` 可以同时满足多个服务档位。经过高品质审核的低价供给可以服务高品质 Token；这不属于跨档兜底。
- 一次用户请求始终使用 Token 选择的服务档位，重试和平台兜底不得切换档位。
- 四档 `GroupRatio` 继续固定为 `1`；最终用户扣费使用实际命中供给的倍率。
- 修复按小批次进行，每批包含行为测试、失败路径测试和文档更新，不同时重写全部核心链路。

## 批次 A：倍率语义与配置一致性

优先级：最高。先完成本批，再继续扩展动态权重和容量算法。

- [x] 删除高品质默认值 `100` 的伪无限语义，默认价格保护改为 `1.0`，前后端统一使用 `x` 单位；读取旧值恰好为 `100` 的未上线配置时兼容归一为 `1.0`。
- [x] 将 Ability 从“每个供给只进入一个档位”改为“按每个 Token 档位独立判断资格”，支持一个 `Channel + Model` 同时进入多个档位。
- [x] 高品质候选必须同时满足管理员质量审核和价格保护；提高售价不能自动获得高品质资格。
- [x] 边界值必须全部为有限正数；特价、经济、标准边界严格递增，高品质最高倍率作为独立价格保护校验。
- [x] 增加专用的路由配置保存接口，一次事务保存完整配置，只重建一次 Ability。
- [x] 配置保存失败时不得更新前端基线；后端检查数据库写入和 Ability 重建错误后才发布运行时配置。
- [x] 路由运行时配置改为受保护的不可变快照，避免请求读取与配置发布并发读写 map/slice。
- [x] 增加确定性端到端回归，覆盖供给探测上架、服务档位 Token、渠道商优先、同档兜底、最终扣费、最终渠道商收益和 `hub_attempts` 尝试链。
- [ ] 系统设置加载失败时页面显示错误和重试，禁止使用前端默认值覆盖真实生产配置。
- [x] Token 创建不检查瞬时供给可用性；运行时同档候选耗尽时固定返回 HTTP `503`、`error.code = service_tier_unavailable` 和 `request_id`。不跨档、不禁用或修改 Token，供给恢复后同一 Token 的下一次请求直接恢复。
- [x] Token 创建和完整更新接口在档位路由启用时强制校验四档，拒绝空值、`auto`、任意字符串和不允许的旧分组；注册接口生成的初始 Token 固定使用 `medium`。仅状态更新与历史 Token 读取不受影响，关闭档位路由后保留旧分组写入兼容。
- [ ] 管理员固定 Channel Token 必须校验服务档位 Ability 和子域渠道商归属，不能绕过同档路由。
- [ ] 高品质渠道商选择器支持分页或搜索，不受后台单页 100 条上限影响。
- [x] 配置变更、模型定价变更和版本升级启动时正确重建相关 Ability，并在成功后刷新缓存。
- [ ] 模型家族分类不能只依赖零散名称规则；首版至少覆盖已定价的文本、图片、音频、Embedding 和 Moderation 模型。

验收：`100` 不再出现为默认倍率；低价且已审核的优质供给可服务高品质 Token；多字段保存不会暴露中间配置；非法 Token 分组无法通过 API 创建。

## 批次 B：循环保护与路由安全

- [x] `request_loop_detected` 具有终止语义，不进入普通状态码重试、计费或结算；第三方普通 `508` 仍保留现有可配置重试语义。
- [x] `request_loop_detected` 固定排除 Channel 自动禁用；即使管理员显式把 `508` 加入自动禁用状态码范围，平台生成的循环错误也不会关闭渠道。
- [x] `channel:model_mapped_error` 只记录模型/端点级失败，不触发 Channel 级自动禁用，避免一个模型映射错误误伤同渠道其他模型。
- [x] `channel:endpoint_unsupported` 用于端点不匹配或适配器明确不支持的请求；该错误只影响本次 `Channel + Model + Endpoint` 尝试，允许同档重试且不触发 Channel 级自动禁用。上游 `model_not_found` 同样不触发整条 Channel 自动禁用。
- [x] 多端点模型按现有探测 `ProbeKind` 隔离文本与图片资格；一类探测失败不会删除另一类健康端点的模型 Ability。缓存、数据库直查和 Affinity 命中均按当前请求类型复查，全部探测类型失败后才让该模型退出路由。
- [ ] 在 JSON 指纹之外补充适用于 multipart、表单、任务和 WebSocket 的循环保护；优先采用受控 hop 标记，指纹作为第二层保护。
- [x] 渠道亲和命中时同时检查 Channel、供给扩展和渠道商均为启用状态；拒绝后清除失效亲和。
- [x] 服务档位在数据库直查和内存缓存路径都严格排除本次已失败 Channel；普通 New API 分组在候选全部尝试后仍保留原有复用行为。
- [ ] 明确服务档位重试预算恰好耗尽时的最终错误契约：当前返回最后一个上游错误；只有下一次选路确认无候选时才返回 `service_tier_unavailable`。
- [ ] 路由候选、渠道归属和供给倍率使用同一版本的不可变快照原子切换。
- [ ] 供给归属或倍率快照缺失时失败关闭，不得自动当作平台自营渠道和基础倍率继续请求。
- [ ] 上架状态、可路由 Ability 和缓存刷新保持一致；事务或进程失败不能留下“已下架但仍可路由”等状态。
- [ ] 保留旧 `auto` 分组兼容时，渠道商优先与平台兜底不得破坏原有重试计数状态。
- [ ] 候选规模增加前预计算模型/档位/渠道商桶，避免每次请求扫描、分组和排序全部候选。

验收：模拟平台与渠道商互相回流时在固定跳数内终止；停用渠道商不会通过亲和继续命中；缓存刷新失败时保留旧的完整快照而不是进入混合状态。

## 批次 C：扣费、退款与渠道商收益

- [ ] 明确高价重试的余额策略。默认建议在发起下一次上游请求前原子预留差额，余额不足则停止；若允许平台赊账，必须成为显式配置和可审计状态。
- [ ] 失败请求退款改为以 `request_id` 幂等、可重试的持久化流程；不能在实际退款成功前永久标记完成。
- [ ] 用户扣费与渠道商收益使用可恢复的一致性流程；收益准备失败不能被静默忽略。
- [ ] 用户资金已提交但 Token 调整失败时，不能错误取消渠道商收益；结算结果需区分“未扣费”和“资金已提交、待对账”。
- [ ] 同步请求在用户扣费后崩溃时，后台能够扫描和完成待结算收益。
- [ ] 异步任务使用提交时保存的模型价格和倍率快照，不得按任务完成时的当前配置重新定价。
- [ ] 异步任务只有在用户最终差额结算和额度持久化成功后才能结算渠道商收益。
- [ ] 失败但上游可能扣费的人工补偿关联 `request_id + attempt_index`，并具有唯一幂等约束。
- [ ] 首版提现后端固定 CNY，实际金额和有效汇率由服务端按统一舍入规则计算，不信任任意客户端币种或汇率。

验收：注入数据库失败和进程中断后，用户余额、Token 额度、渠道商收益都能通过幂等重试收敛；同一请求不会重复扣费、重复退款或重复结算。

## 批次 D：日志、审计与隐私

- [x] 短窗口同时保留全尝试成功率和可切换成功率；客户端错误、循环保护和客户端主动断开不污染渠道健康，状态码映射前的原始上游状态只用于观测归因。
- [ ] 服务档位请求无论消费日志或错误日志开关如何，都至少保存一条最终请求审计记录。
- [ ] 一次客户端请求只产生一条请求级最终记录；失败尝试保存在结构化尝试数组中，不按重试次数重复计算失败请求。
- [ ] 完整 `hub_attempts` 放入管理员可见区域；普通用户只看到渠道商、是否兜底、实际倍率、耗时和结果等允许字段。
- [ ] 流式中断、超时、客户端断开和软错误不能被硬编码为成功；结果需区分成功、部分成功和失败，并单独记录扣费状态。
- [ ] 任务请求的全部失败路径，包括 `LocalError`，必须记录尝试链和最终失败。
- [ ] 异步任务退款、调账和结算日志沿用原始 `request_id`。
- [ ] Midjourney 等旧路径补齐请求开始时间、供给归属、倍率、成功和失败尝试记录。
- [ ] TTFT 只在收到有效文本或推理增量时记录；非流式和非文本端点不写伪造的首字时间。

验收：普通用户接口不暴露内部 Channel 或上游请求 ID；任意成功、失败、重试、流式中断和异步任务都可按同一 `request_id` 还原完整链路。

## 批次 E：数据兼容与发布

- [ ] 供给倍率避免 PostgreSQL `REAL` 单精度边界漂移，改用固定精度数值或固定点整数比较。
- [ ] 迁移采用 expand/contract；新版本稳定运行前不删除旧节点仍依赖的列。
- [ ] 混合版本期间禁止创建旧节点无法识别的服务档位 Token，或明确要求停机升级。
- [ ] 增加 SQLite、MySQL、PostgreSQL 的边界值与迁移测试。
- [ ] 增加配置并发更新 `-race`、缓存刷新失败、结算崩溃恢复和高候选量基准测试。

验收：三种数据库在 `0.1`、`0.3`、`0.8`、`1.0` 等边界得出相同档位资格；升级和回滚期间不会破坏旧实例读取或现有 Token。
